# Правила работы с кодом

Коротко: код и документация в этом репозитории пишутся так, чтобы следующий человек понял
решение без пересказа. Ниже — то, что проверяется на каждом шаге.

## Общение и язык

- Обсуждение задач, отчёты, комментарии к коммитам в переписке — **по-русски**.
- В коде: имена, комментарии и doc-комментарии — **по-английски**; сообщения об ошибках,
  сообщения тестов и вывод командной строки — **по-русски**. Пользователь читает ошибки,
  а не исходники.
- README — только по-английски, без кириллицы. Документация в `docs/` — по-русски.

## Ошибки

- В рабочем коде нет `unwrap()` и `panic!`. Ошибка возвращается значением.
- У каждого модуля свой тип ошибки на `thiserror`; текст ошибки объясняет, **что именно**
  не удалось, а не «ошибка». Если отказ пришёл из внешней библиотеки, её текст сохраняется.
- `expect()` допустим только там, где причина отказа неустранима и сообщение это объясняет:
  отравленный мьютекс, нарушенный инвариант. «На всякий случай» — не причина.
- Ошибка должна быть видна **до** начала работы, а не после первой фразы: занятый адрес,
  недоступный файл и отсутствующий ключ проверяются при сборке приложения.
- Молча глотать отказ нельзя. Приёмник, который ещё не умеет доставлять, обязан сказать
  об этом, а не делать вид, что перевод доставлен.

## Аудио

- На аудиопотоке не выделяется память и не берутся блокировки. Аудио передаётся дескриптором
  (`transono::audio::Audio`, внутри `Arc`), а не копией сэмплов.
- Приведение формата (частота, каналы, тип сэмпла) делает приёмник, а не ядро.

## Публичные интерфейсы

- `#![warn(missing_docs)]` включён: у каждого публичного элемента есть doc-комментарий.
- Doc-комментарий объясняет смысл и договорённость, а не пересказывает сигнатуру. Если
  решение неочевидно — почему так, а не иначе.
- Изменение публичного интерфейса — повод обновить `docs/decisions.md` или ТЗ, если решение
  влияет на структуру проекта.

## Тесты

- Тест проверяет то, что обещает его имя. Если имя расходится с проверкой — правится имя или
  проверка, но не «примерно так».
- Тесты не помечаются `#[ignore]`.
- Сообщения в проверках — по-русски и объясняют, что именно нарушено.
- Порог вердикта задаётся **до** данных. Результат, противоречащий ожиданию, — тоже
  результат; подгонять данные под ожидание нельзя.
- Прогон на реальных данных — до интеграции, а не после.

## Сборка и проверки

Сборка идёт только через `nix develop`, целевой каталог — вне репозитория:

```bash
cd ~/projects/RUST/ai-translator
export CARGO_TARGET_DIR=$HOME/.cache/ai-translator-target

nix develop --command bash -c 'cargo test'
nix develop --command bash -c 'cargo clippy --all-targets -- -D warnings'
nix develop --command bash -c 'cargo fmt --check'
```

- `clippy` без предупреждений; `fmt --check` без расхождений.
- `target/` в каталоге проекта не создаётся: каталог принадлежит `nobody`, запись туда
  падает.
- Права на файлы проекта не правятся через `sudo`/`chown`/`chmod`. Ошибка доступа —
  сообщить, а не «починить» правами root.

## Git

- `git add` и `git commit` — только по явной просьбе. `git push` делает владелец проекта.
- Коммит — одно законченное изменение с внятным заголовком; в теле — почему, а не что.

## Границы

- Правки кода и конфигураций, влияющие на чужой стенд (боевая база, сервисы), — только после
  подтверждения владельца.
- Секреты — только через переменные окружения (`*_env`) или `.env`; в конфигурации и в коде
  их нет.
