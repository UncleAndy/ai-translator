# Релизы

Тег `v*` запускает `.github/workflows/release.yml`: он собирает артефакты под три платформы, считает контрольные суммы и складывает всё в один архив-артефакт `release-<тег>` на странице прогона. **Релиз на GitHub создаёт человек.** Workflow к API релизов не обращается и прав на запись не запрашивает (`permissions: contents: read`).

## Что попадает в релиз

| Артефакт | Платформа | Требования на машине |
|---|---|---|
| `ai-translator-<версия>-x86_64-linux.tar.gz` | Linux x86_64 | `libpipewire-0.3-0` ≥ 1.0, `libasound2`, glibc ≥ 2.34 |
| `ai-translator_<версия>_amd64.deb` | Ubuntu 24.04+, Debian 13+ | то же, объявлено в `Depends` |
| `ai-translator-<версия>-1.x86_64.rpm` | Fedora 40+, RHEL 10+ | то же, объявлено в `Requires` (`pipewire-libs >= 1.0`) |
| `ai-translator-<версия>-x86_64.AppImage` | любой Linux x86_64 | те же библиотеки **в системе**: внутрь образа они не упаковываются |
| `ai-translator-<версия>-aarch64-macos.tar.gz`, `.dmg` | macOS на Apple Silicon | ничего |
| `ai-translator-<версия>-x86_64-macos.tar.gz`, `.dmg` | macOS на Intel | ничего |
| `SHA256SUMS` | — | контрольные суммы всех файлов |

**Почему PipeWire ≥ 1.0.** `libspa-sys` генерирует биндинги из системных заголовков PipeWire: на 0.3.48 (Ubuntu 22.04) сборка падает на `spa_meta_first` и полях `spa_video_info_raw`. Поэтому сборочный раннер — `ubuntu-24.04` (PipeWire 1.0.5), и то же требование переносится в зависимости пакетов. Пол glibc при этом остаётся 2.34 — измерено на собранном бинарнике.

**Почему AppImage без библиотек.** PipeWire и ALSA — клиентские библиотеки с загружаемыми модулями; упакованные внутрь образа, они расходятся с демоном на хосте. Отсюда: AppImage даёт «без установки», но не «без зависимостей».

## Как выпустить

1. Поднять версию в `Cargo.toml`. Тег обязан совпасть с ней — workflow это проверяет и падает, если разошлись.
2. `git tag v0.1.0 && git push origin v0.1.0`.
3. Дождаться зелёного прогона `release`.
4. На странице прогона скачать артефакт `release-v0.1.0` — внутри все файлы и `SHA256SUMS`.
5. Создать релиз вручную: Releases → Draft a new release → выбрать тег → приложить файлы из архива (сам `SHA256SUMS` тоже) → опубликовать.

## Подпись и Gatekeeper

Ничего не подписано, ключей в workflow нет.

- **macOS.** После `strip` бинарник подписывается ad-hoc (`codesign --force --sign -`): без подписи arm64 не запускает программу вовсе. Но Developer ID нет, нотаризации нет — Gatekeeper считает приложение неподписанным. Первый запуск: правый клик → «Открыть», либо `xattr -d com.apple.quarantine ./ai-translator`.
- **Linux.** Пакеты не подписаны (нет GPG-ключа), контрольные суммы лежат в `SHA256SUMS`.

## Локальная проверка

- `packaging/build-linux.sh` — в обычном дистрибутиве, в CI это `ubuntu-24.04`. Из Nix-окружения собирать нельзя: бинарник получает интерпретатор `/nix/store/.../ld-linux-x86-64.so.2` и вне Nix не стартует.
- `packaging/build-macos.sh` — на macOS с командными инструментами Xcode; без `hdiutil` диск пропускается.
- Рабочие каталоги `dist/` и `build/` — в `.gitignore`.

Проверено в контейнере `ubuntu:24.04` 18 октября 2026: собираются и tar.gz, и `.deb` (`Depends` на месте), и `.rpm`, и AppImage; интерпретатор `/lib64/ld-linux-x86-64.so.2`, RUNPATH пуст, максимальный требуемый символ glibc — 2.34. AppImage распаковывается и запускается, на хосте без PipeWire честно падает на `dlopen`.
