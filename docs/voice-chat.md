# Трансляция перевода в голосовой чат Telegram

Этот документ описывает сборку с приёмником `telegram_call` — тем, который подаёт
переведённую речь в голосовой чат группы или канал. Состояние на сегодня: движок
подключён и проверен, вход в аккаунт и подача звука ещё пишутся.

## Чем это не является

- Это **не** Bot API. Бот в голосовой чат не входит: Telegram не пускает ботов в
  звонки, поэтому все методы — MTProto и работают от имени пользовательского
  аккаунта.
- Это **не** голосовые сообщения. Живой звук идёт непрерывно, пока работает
  переводчик.

## Что нужно до первого запуска

1. `api_id` и `api_hash` приложения с <https://my.telegram.org> → API development
   tools. В конфигурацию они не пишутся: только имена переменных окружения.
2. Аккаунт Telegram, который будет вещать. Он должен состоять в группе или быть
   администратором канала с правом «Управление видеочатами» (`manage_call`).
3. Канал или группа, где идёт проверка: числовой id или `@name`.
4. Сессия аккаунта: команда `telegram-login` (появится вместе с остальным кодом)
   спросит номер и код; файл сессии — полный доступ к аккаунту, хранится с правами
   `0600` и в репозиторий не попадает.

## Сборка варианта с трансляцией

Движок — нативная библиотека `libntgcalls` (C++ WebRTC, LGPL-3.0). Готовые сборки
есть для Linux x86_64, Linux arm64 и macOS arm64; для остальных целей фича не
собирается, и включённый приёмник отвергается проверкой конфигурации.

```bash
# 1. Библиотека движка под текущую цель (складывается в build/ntgcalls/<target>)
bash packaging/fetch-ntgcalls.sh

# 2. Сборка с фичей: путь к библиотеке и её зависимости (zlib, libstdc++)
LIB=$PWD/build/ntgcalls/$(rustc -vV | sed -n 's/^host: //p')/lib
ZLIB=$(nix eval --raw nixpkgs#zlib.outPath)
CXX=$(nix eval --raw nixpkgs#stdenv.cc.cc.lib.outPath)

NTGCALLS_DYLIB=$LIB/libntgcalls.so \
NTGCALLS_LIB_DIR=$LIB \
RUSTFLAGS="-L $ZLIB/lib -C link-arg=-lz -C link-arg=-Wl,-rpath,$LIB" \
nix develop --command bash -c \
  "export LD_LIBRARY_PATH=$LIB:$CXX/lib:$ZLIB/lib; cargo build --features telegram-call"
```

На обычном дистрибутиве (не NixOS) `zlib` и `libstdc++` лежат в системе, и
`RUSTFLAGS` с путями Nix не нужны: достаточно `NTGCALLS_DYLIB` и `NTGCALLS_LIB_DIR`.

## Что уже проверено

- `cargo test --features telegram-call --test telegram_call_engine` поднимает
  движок и получает от него параметры входа для `phone.joinGroupCall`: `ufrag`,
  `pwd`, `fingerprints`, `ssrc`. Это значит, что библиотека линкуется, грузится и
  отвечает — то есть фундамент транспорта рабочий.
- Сборка без фичи остаётся чисто-Rust: `cargo test` проходит без нативной
  библиотеки, а конфигурация с включённым `telegram_call` останавливает запуск с
  объяснением, что эта сборка так не умеет.

## Что ещё не сделано

- `telegram-login`: вход по номеру и коду, файл сессии.
- Поиск или создание голосового чата в канале/группе и вход в него.
- Подача кадров перевода в звонок и выход из него на остановке.
- Упаковка библиотеки в релизные пакеты и приёмка на живом звонке.

До этого включённый приёмник на сборке с фичей завершается ошибкой «трансляция в
голосовой чат ещё не подключена в этой ревизии» — это честное состояние работы, а
не отказ функции.
